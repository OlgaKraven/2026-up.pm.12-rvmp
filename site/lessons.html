ПМ.12 / Создание, объяснение и проверка

Как устроена работа

  1. 1

    Один маршрут в своём проекте

    В проекте PM12_VariantNN сначала проверим движение, затем контакты и завершение, после этого реализуем правило своей карточки. Код «Кристального маршрута» — разобранный образец общей основы в том же рабочем проекте. Вторую игру для сдачи создавать не нужно.

  2. 2

    Контрольные точки

    Сначала работают три файла и движение. Затем добавляются взаимодействия и полный GameManager. Проверяем общую игру, только после этого переносим механику на вариант. Когда фрагмент временно зависит от следующего, это прямо указано: не пытайтесь исправлять ожидаемые ошибки незаконченного блока.

  3. 3

    Тестовый проект для сверки

    Тестовый проект для сверки

    Если собственная основа ведёт себя иначе, откройте тестовый проект в отдельной папке и сравните нужный файл или состояние. Он не является обязательным вторым результатом и не содержит решения индивидуального правила.

Проверьте редактор кода и систему ввода

  1. 1

    Редактор скриптов

    В Unity откройте Unity → Settings на macOS или Edit → Preferences на Windows, затем External Tools. В External Script Editor выберите уже установленный редактор C#. Если VS Code не установлен, используйте доступный редактор; не требуется устанавливать другой ради примера.

  2. 2

    Система ввода

    Откройте Edit → Project Settings → Player → Other Settings → Configuration → Active Input Handling. Для кода Input.GetKey выберите Input Manager (Old), либо Both, если проекту также нужен Input System. Подтвердите перезапуск редактора, если он запрошен. Это настройка текущего учебного проекта. Если поле свёрнуто, раскройте Other Settings и Configuration.

  3. 3

    Почему это нужно

    Unity поддерживает две системы ввода. В примере используются UnityEngine.Input.GetKey и GetKeyDown старой системы. Только Input System Package (New) не подходит этому коду. При InvalidOperationException прочитайте сообщение и повторно проверьте Active Input Handling.

  4. 4

    Размер окна проверки

    Вкладка Game → список разрешений → 16:9. Если строки нет, нажмите +, выберите Aspect Ratio, Width 16, Height 9 и сохраните. Демонстрация использует горизонтальное поле; портретный экран требует отдельной переработки камеры и интерфейса.

  5. 5

    Проверка

    После перезапуска Main открыта. Дважды щёлкните новый скрипт: открывается выбранный редактор. Пока код не введён, Play не требуется.

    Почему так

    Awake делает коллайдер триггером и сохраняет масштаб. Update вращает и пульсирует изображение; Time.deltaTime делает скорость независимой от числа кадров. OnTriggerEnter2D отбирает именно PlayerController, затем передаёт предмет менеджеру. Сам предмет не решает, наступила ли победа.

        private static Sprite CreateSprite(Shape shape, Color color)
    {
        const int size = 64;
        var texture = new Texture2D(size, size, TextureFormat.RGBA32, false);
        texture.filterMode = FilterMode.Bilinear;
        for (int y = 0; y < size; y++)
        {
            for (int x = 0; x < size; x++)
            {
                float nx = (x + 0.5f) / size * 2f - 1f;
                float ny = (y + 0.5f) / size * 2f - 1f;
                bool inside = shape switch
                {
                    Shape.Circle => nx * nx + ny * ny <= 0.90f,
                    Shape.Diamond => Mathf.Abs(nx) + Mathf.Abs(ny) <= 0.92f,
                    Shape.Cross => Mathf.Abs(nx - ny) < 0.22f || Mathf.Abs(nx + ny) < 0.22f,
                    Shape.Exit => Mathf.Max(Mathf.Abs(nx), Mathf.Abs(ny)) <= 0.92f &&
                                  Mathf.Min(Mathf.Abs(nx), Mathf.Abs(ny)) >= 0.22f,
                    _ => true
                };

            }

Для 01, 02, 04, 06, 21, 23–25 оставьте отдельный контакт с местом завершения или доставки: в Collect победу не вызывайте. Для доставок и вместимости победа считается по Delivered, после разгрузки. Для 26–30 результат требует также достижение выхода/цели согласно карточке.

  3. 3

    Проверка состава

    В 21/25 два предмета типа 0 не заменяют реагент типа 1. Третий тип не обязателен и не должен блокировать финиш. В 22–24 повтор первого типа не заполняет второй и третий. Проверьте неполный состав, полный состав, лишний предмет и сброс каждого счётчика.

ПМ.12 / Уточнения самостоятельного правила

Ключ в замке, мосты и спасённый робот

  1. 1

    Ворота варианта 26

    Храните флаги ключей через Access и дополнительно bool gateAOpened, gateBOpened. В Collect ключ только вызывает access.Activate; ворота здесь не отключайте. Создайте KeyGate по образцу ExitZone, добавьте public int keyIndex; public Collider2D barrier;. Вместо TryFinishLevel вызовите GameManager.Instance.TryOpenGate(keyIndex, barrier);. В GameManager добавьте метод, который проверяет IsPlaying и access.Enabled(index), затем отключает barrier.enabled и ставит соответствующий gateOpened=true. Создайте перед стеной отдельную зону с BoxCollider2D isTrigger=true и KeyGate, задайте индекс 0/1 и ссылку на collider соответствующей стены. TryFinishLevel проверяет оба gateOpened и контакт с выходом, а RestartGame сбрасывает оба признака и включает барьеры.

  2. 2

    Мосты варианта 29

    В GameManager рядом с Access добавьте Sequence bridgeOrder. До access.Activate в Collect проверяйте bridgeOrder.Take(item.itemIndex, false); при отказе учитывайте ошибку/падение и return. Присвойте трём зарядам номера 1–3. Три барьера символизируют закрытые участки маршрута; после правильного заряда отключайте только барьер с номером itemIndex. В RestartGame вызывайте bridgeOrder.Reset и включайте все три барьера. Финиш: access.All(3) и контакт с порталом. Проверка: второй заряд первым не открывает участок; первый разрешает только первый участок; повтор не заменяет следующий.

  3. 3

    Робот варианта 30

    Считайте управляемый Player роботом, а экранные кнопки — пультом оператора; явно подпишите это в интерфейсе. Два разных рубильника устанавливают Access-флаги и снимают collider двери при All(2). Само открытие двери не вызывает победу. ExitZone принимает физический контакт именно PlayerController робота, а TryFinishLevel проверяет All(2). Повтор рубильника учитывайте как ошибку системы, не как второй флаг; при третьей ошибке Lost. В RestartGame сбрасывайте Access, ошибки, дверь и позицию робота. Проверьте повтор первого рубильника, второй рубильник, открытие двери без победы, затем реальное движение робота до выхода.

  4. 4

    Повтор рубильника в варианте 30

    Рубильник должен остаться на сцене после активации, иначе повторить контакт с ним невозможно. Для этого в ветви варианта 30 не выполняйте Remove и Destroy. После принятой access.Activate обновите состояние двери и завершите Collect через return. В отказе повторной Activate увеличьте отдельный счётчик системных ошибок и завершите обработчик. Проверяйте новый вход после выхода из триггера, а не каждый кадр пребывания внутри. При RestartGame восстановите ошибки и Access; рубильники остаются доступными.

ПМ.12 / Создание, объяснение и проверка

Перенос правила на свою предметную область

  1. 1

    Сопоставьте сущности

    Составьте соответствие: Crystal → предмет области; Hazard → её опасность; Exit → место завершения или разгрузки. Запишите номер/тип, изменение состояния, отказ и условие завершения. У каждого предмета должно быть понятное действие, а у каждого состояния — место сброса.

  2. 2

    Различия внутри группы

    Не все карточки требуют одинакового штрафа. Уточните сброс последовательности, повреждение, замедление, вместимость, количество доставок, состав набора и связи двери с ключом.   3. 3

    Сначала замените данные и подписи; проверьте исходную игру. Затем измените принятие контакта, затем интерфейс и условие финиша, затем полный сброс. После каждого законченного изменения сохраните, скомпилируйте и выполните конкретную проверку. Не переносите сразу все шесть механик.

Этап 2 / До переноса в Unity

Дополнительно: как подготовить скачанный файл

  1. 1

    5. Распакуйте архив

    Откройте папку Downloads или «Загрузки». Дважды щёлкните скачанный ZIP. Откройте распакованную папку и найдите каталог PNG, Sprites или отдельно нужный .png-файл.

  2. 2

    6. Выберите подходящее изображение

    Для игрока выберите один вид сверху или простой значок. Для предмета и опасности используйте разные силуэты. Прозрачный фон отображается в графическом редакторе клетчатым полем. JPG для объектов с прозрачностью не подходит.

  3. 3

    7. Переименуйте файл

    Используйте короткое имя латинскими буквами без пробелов: player.png, crystal.png, hazard.png, exit.png, wall.png. Не оставляйте имена вида image (1).png — их легко перепутать.

  4. 4

    8. Не переносите весь архив

    В Unity копируйте только выбранные PNG и файл лицензии. Не помещайте в Assets исходный ZIP, рекламные изображения, PSD-файлы и ненужные варианты — они увеличивают проект и замедляют импорт.

Этап 2 / Project → Assets → Art → Sprites

Дополнительно: как загрузить картинку в Unity

  1. 1

    9. Создайте папки

    В Project нажмите Assets. Щёлкните правой кнопкой → Create → Folder, введите Art и нажмите Enter. Дважды щёлкните Art, снова создайте Folder с именем Sprites и откройте её. Вверху Project должен быть путь Assets > Art > Sprites.

  2. 2

    10. Способ через перетаскивание

    Откройте Finder на macOS или Проводник на Windows. Уменьшите окно так, чтобы одновременно видеть файл и Unity. Перетащите player.png в свободное место окна Project внутри Assets/Art/Sprites. Отпустите кнопку мыши и дождитесь импорта.

  3. 3

    11. Способ через меню

    Если перетаскивание неудобно, в Unity выберите Assets → Import New Asset. В открывшемся окне найдите PNG, нажмите его один раз, затем нажмите Import. Файл появится в текущей папке Project.

  4. 4

    12. Проверьте результат

    В Project появилась миниатюра с именем файла. Если вместо неё виден белый документ или Unity показала красную ошибку, проверьте расширение .png и откройте Console. Не переименовывайте импортированный файл вне Unity после его использования.

Этап 2 / Inspector → Apply

Дополнительно: настройки картинки

  1. 1

    13. Выделите PNG

    Один раз нажмите player.png в Project. Справа откроется Texture Import Settings. Если Inspector пуст, выберите Window → General → Inspector и снова нажмите файл.

  2. 2

    14. Установите тип Sprite

    В поле Texture Type выберите Sprite (2D and UI). В Sprite Mode выберите Single. Pixels Per Unit установите 100. Mesh Type выберите Full Rect. Включите Alpha Is Transparency, если у PNG прозрачный фон.

  3. 3

    15. Выберите фильтрацию

    Для обычной гладкой графики выберите Filter Mode: Bilinear. Для пиксельной графики выберите Point (no filter), иначе края станут размытыми. Compression для учебного проекта установите None.

  4. 4

    16. Нажмите Apply

    Внизу Inspector нажмите Apply. Не переходите к другому файлу до нажатия. Повторите пункты 13–16 для crystal.png, hazard.png, exit.png и wall.png. Эти параметры соответствуют рекомендациям Unity для Sprite (2D and UI).

ПМ.12 / Создание, объяснение и проверка

Дополнительно: как подключить PNG к автоматически созданному объекту

  1. 1

    Папка и загрузка

    Импортируйте нужный спрайт, затем в Assets создайте Resources и перенесите в него player.png. Resources.Load<Sprite>("player") ищет имя без расширения внутри Resources. Это простой вариант для учебной игры; исходное изображение должно иметь Texture Type Sprite (2D and UI).

  2. 2

    Замените назначение renderer.sprite в CreateSpriteObject

    Sprite picture = name == "Player" ? Resources.Load<Sprite>("player") : null;
renderer.sprite = picture != null ? picture : CreateSprite(shape, color);
  3. 3

    Место и проверка

    Assets/Scripts/GameManager.cs, CreateSpriteObject: замените только renderer.sprite = CreateSprite(shape, color);. Сохраните и запустите Game. Изменяется игрок, остальные фигуры сохраняются. Если картинка не загрузилась, геометрический спрайт остаётся: проверьте Resources, имя и тип импорта. Не добавляйте ручного Player в Hierarchy рядом с автоматически созданным.
