# Обновление комплекта

## Где менять содержание

Учебный текст находится в `content/course.json`: паспорт и задание — в `assignment`, варианты — в `areas`, пошаговый материал — в `guide`. Не создавайте второй JSON с тем же содержанием.

Код редактируется только в `unity-project/Assets/Scripts`. В блоке инструкции с видом `code` укажите `code_file` и полуинтервал строк `code_lines: [start, end]`. Сборщик сам вставит код. Проверка требует, чтобы диапазоны покрывали каждый учебный файл полностью, без пропусков и повторов.

Снимок задаётся блоком `kind: image`, полями `path`, `text` и `alt`. Исходные снимки хранятся в `unity-project/Documentation/Screenshots` и автоматически копируются на сайт.

## Методические правила

- Одна практика содержит одно общее задание с последовательными этапами.
- Код вводится логическими порциями: поле, метод или класс с точным местом вставки, объяснением и наблюдаемой проверкой.
- Термин объясняется до первого использования.
- После небольшого блока действий указывается ожидаемый результат и способ исправления типичной ошибки.
- Варианты должны отличаться программным правилом, а не только названиями или цветами.
- Не упоминайте способности или предполагаемые особенности студентов.
- Не добавляйте часы, реквизиты или официальные критерии без подтверждённых данных.

## Контроль перед публикацией

Черновик собирается в `work/site`, а не поверх сохранённого `site`. Для сборки нужны Python с зависимостями `requirements.txt`, Node.js и Playwright из `package.json`. Можно использовать уже доступный рабочий runtime: `NODE_BIN` задаёт путь Node.js, `NODE_PATH` — каталог модулей. Сам сборщик ничего не устанавливает. Профиль PDF — A4, книжный «блоки + маршрут» с локальным Golos Text.

Сначала выполните `python scripts/build_report.py`: он адаптирует копию общего мастера `forms/template/Отчет о выполнении.docx`, сохраняя его стили и остальные части. `python scripts/check_rules.py` проверяет шесть чистых моделей C# и извлечённое тело Collect; нужен имеющийся .NET SDK 10 (`DOTNET_BIN` при необходимости). Этот тест не запускает Unity, физику, ввод и сцену и не заменяет пункты ниже.

Для блоков `snippet_file` поле `text` синхронизируется с файлом для прямого импорта в EatDoners. Сборщик отвергает расхождение; текстовое поле не редактируется как самостоятельный источник кода.

Отпечатки текстовых исходников и подготовленных текстовых файлов считают переводы строк в едином LF, чтобы checkout Git на Windows и Linux не менял результат проверки. Бинарные ресурсы сравниваются побайтово. Тестовый ZIP также сохраняет текст в LF и имеет фиксированные метки времени; повторная сборка не меняет его без изменения содержания.

1. Откройте `unity-project` в указанной версии Unity.
2. Убедитесь, что Console не содержит красных ошибок.
3. Проверьте управление, сбор, опасность, неполный выход, победу, поражение и повтор.
4. Выполните `python scripts/build.py` и `python scripts/check.py` для черновика в `work/site`. Проверьте форму в Word, её PDF-представление и заполнение полей с настоящим изображением на отдельной контрольной копии.
5. Отрисуйте оба PDF и просмотрите каждую страницу, особенно код, переходы и ссылки вариантов 01, 15 и 30. `assignment.pdf` — задание и методические рекомендации, `guide.pdf` — отдельный список предметных областей.
6. Проверьте ранний проект из трёх файлов, полный пример и шесть моделей правил; сверяйте различия всех 30 карточек. Проверьте ссылки на PDF, ZIP, исходники и шаблон отчёта.
7. Сохраните реальные доказательства и итоговую сверку аудита локально. Установите `meta.status=ready`, заново соберите и проверьте неизменённый комплект. В игнорируемом `verification/release.json` укажите `source_sha256` из `source_fingerprint()` и фактически подтверждённые `checks`: `unity`, `variants`, `visual`, `audit`. Не ставьте отметки без доказательств.
8. Выполните `python scripts/build.py --release` и `python scripts/check.py --release`. Сборщик отвергает устаревший отпечаток исходников. Публикуйте только этот подготовленный `site`: Actions проверяет его и не пересоздаёт PDF другим шрифтом.
9. После публикации проверьте удалённый SHA и скачивание актуальных материалов.

### Публикация проверенных материалов без запуска Unity

Для согласованного выпуска методических материалов можно установить `meta.status=materials-ready`. В этом режиме сборщик берёт оба проверенных PDF из `materials/` без изменений и включает их в отпечаток исходников. Проверьте текст, вёрстку, 30 вариантов, ссылки, форму отчёта и тестовый ZIP. В локальном `verification/release.json` укажите актуальный отпечаток и результаты `unity: false`, `variants: true`, `visual: true`, `audit: true` после этих проверок. Затем соберите и проверьте `site` обычными командами с `--release`. Для выпуска с отметкой о проверке Unity по-прежнему нужен статус `ready` и весь цикл выше.

Ранний временный GameManager хранится в `tutorial/` и вставляется через `snippet_file`. Он заменяется полной версией, а не добавляется рядом с ней. Варианты представлены 30 плоскими карточками в `areas`. Индивидуальные стенды не требуются: студент создаёт свой проект, исходные условия находятся в карточке. Тестовый проект имеет отдельную ссылку. Форма «Отчет о выполнении.docx» адаптируется из сохранённого общего мастера по этапам `report`. Запрещены баллы, объём и распределение учебного времени, выдуманные обязательные формы сдачи. При сдаче проекта приложите ссылку на его репозиторий.
