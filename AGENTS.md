# Правила проекта практики

- Единственный источник учебного текста — `content/course.json`.
- Единственный источник программного кода — файлы в `unity-project/Assets/Scripts`; сайт, PDF и загрузки получают код из них.
- Одна практика — одно задание с этапами. Связь с другими практиками указывается только при необходимости.
- На сайте остаются три раздела: «Задание», «Инструкция и образец», «Предметные области».
- Не создавать раздел «Преподавателю», отдельный повторяющий образец, параллельный генератор или копию JSON.
- Код вводить по логическим границам с точным местом вставки и проверкой законченного изменения. Термин объяснять до применения. После блока действий добавлять проверку и типичную ошибку.
- Не упоминать способности студентов.
- Все 30 вариантов должны содержательно различаться и требовать изменения программного правила.
- PDF: A4, книжный формат «блоки + маршрут», читаемый полный код, номера страниц и реальные статичные снимки без анимации.
- Служебные папки Unity (`Library`, `Temp`, `Logs`, `obj`, `UserSettings`, `Build`) не коммитить и не включать в ZIP.
- Перед публикацией соблюдать `docs/AUTHORING.md`: проверить варианты, оба PDF, материалы и отпечаток исходников. Для полной приёмки требуется запуск Unity. При согласованном выпуске материалов без Unity фиксировать его границы. Выполнить `python scripts/build.py --release` и `python scripts/check.py --release`. Actions публикует только подготовленный проверенный site.

- Не включать баллы, объём и распределение учебного времени, выдуманные обязательные формы сдачи. Использовать заголовок «Список предметных областей», ссылку на репозиторий проекта и общий шаблон отчёта.
